Chapter 03

System Requirements & Architecture Design

Technical Specifications & Three-Tier Security Infrastructure

3.1 Hardware & Software Environment

To ensure smooth and high-throughput execution of hosting daemons, relational databases, and asynchronous REST controllers, precise hardware and software minimum baseline requirements were specified:

Hardware Specifications
  • Processor: Intel Core i3 / AMD Ryzen 3 (Quad Core, 2.4 GHz+)
  • System Memory: Minimum 4 GB RAM (8 GB Recommended for Multi-service pooling)
  • Storage: 10 GB Free SSD space (for databases, vhosts & backup archives)
  • Network Adapter: Standard 100/1000 Mbps Ethernet / Wi-Fi loopback adapter
Software Environment
  • Operating System: Microsoft Windows 10 / 11 (64-bit Architecture)
  • Runtime Platform: Node.js v18.x / v20.x LTS with npm package ecosystem
  • Web Server & DB: Apache HTTP Server 2.4.x & MariaDB 10.4.x (XAMPP Core)
  • Development Tools: VS Code, Git CLI, Chrome DevTools, Postman

3.2 High-Level Architecture (Three-Tier Microservices)

The system implements a decoupled Three-Tier Client-Server Architecture separating graphical presentation, middleware API logic, and persistent storage/services:

Tier 1 (Presentation): Pure HTML5, CSS3 responsive grid, FontAwesome 6, and reactive vanilla JavaScript DOM managers (app.js, mysqlManager.js, fileManager.js, apiTokensApp.js).
Tier 2 (Application & Micro-Routing): Node.js Express server on Port 2083 orchestrating routes, JWT/cookie sessions, CSRF protection, and UAPI compatibility bridges.
Tier 3 (Host Daemons & Persistence): Apache Virtual Hosts on Port 80, MariaDB on Port 3306, Windows filesystem chroot jail, and JSON state persistence.

3.3 Multi-Tier Security, CSRF Tokens & Chroot Jail Model

Hosting control panels represent high-privilege administrative attack surfaces. The system incorporates four discrete defensive rings:

1. Chrooted File System Jail

All file manager operations are trapped inside a strict chroot root (C:\xampp\htdocs). The path resolver validates all target paths against canonical prefixes, rejecting path-traversal attacks (e.g. ../../Windows/System32) with an immediate EACCES_JAIL exception.

2. CSRF Guard & API Exemption

Browser cookie sessions are guarded by cryptographic cpanel_csrf tokens verified on all state-mutating requests (POST, PUT, DELETE). Conversely, programmatic AI and script clients using Bearer tokens automatically bypass CSRF validation.

3. SHA-256 API Token Hashing

Personal Access Tokens (cptok_...) are hashed with SHA-256 before disk persistence. Tokens feature granular ACL scope enforcement (Files, MySQL, Domains, Cron, SSL, Software, Backups, System, Terminal) to limit access radii.

4. Transport & SQL Injection Defense

Helmet middleware injects X-Content-Type-Options, X-Frame-Options, and Strict-Transport headers. All MariaDB database and user provisioning queries utilize parameterized statements and strict regex identifiers (^[a-zA-Z0-9_]{1,64}$).

Architecture Security Audit: Verified 100% resilient against SQL injection, path traversal, cross-site request forgery, and privilege escalation across automated test suites.
