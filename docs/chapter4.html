System Analysis & Modeling (UML & DFD)

Formal Structural Analysis, Use Cases & Data Flow Engineering

4.1 Use Case Modeling & Actor Specifications

System interactions are modeled around three distinct actors: System Administrator, Web Developer, and Autonomous AI Agent:

Administrator
  • Service Daemon Controls
  • MultiPHP & php.ini Directives
  • IP Blocker Firewall Rules
  • Activity Audit Inspection
Web Developer
  • File Tree & Code Editor
  • MySQL Database & Privileges
  • Domain Virtual Hosts & DNS
  • Cron Jobs & Diagnostics
AI Agent
  • Bearer API Token Auth
  • OpenAPI Schema Discovery
  • Execute Single-Tool Gateway
  • Call Authentic cPanel UAPI

4.2 Data Flow Diagrams (Context & Level 1 DFD)

The flow of data from external entities through authentication, service dispatchers, and data repositories:

4.3 Entity-Relationship (ER) Diagram & State Models

The data layer is modeled with normalized relational structures persisted atomically inside cpanel_store.json:

Core Entity Specifications
  • Users: { id, username, passwordHash, role, createdAt }
  • API Tokens: { id, name, tokenHash, scopes, expiresAt, lastUsedAt }
  • Domains: { id, domain, documentRoot, type, phpVersion, sslEnabled }
  • Cron Jobs: { id, schedule, command, description, enabled, lastRun }
  • Error Pages: { code, name, filename, content, enabled }
  • Zone Records: { id, domain, name, type, record, ttl }
State Transitions

Token Lifecycle: Generated (Plaintext revealed once) → Active (SHA-256 validated on each request) → Expired / Revoked (Immediate HTTP 401 rejection).

Cron Task State: Scheduled → Triggered (Timer or Manual 'Run Now') → Process Spawned → Stdout/Stderr Captured → Status Logged (OK/Failed).

Data Integrity Safeguard: All store mutations employ atomic file writes via temporary swap files (tempPath = store.tmp_Date.now()) before synchronous renaming, preventing database corruption during unexpected power cuts.
